# 集成法院报告

裁决范围为 v0.1.0-alpha.1 的本机三节点只读能力闭环。最终有效结果必须同时满足 `LOCAL_VERIFICATION.json` 的测试 exitCode=0、sourceFiles 哈希一致及两个真实运行见证；本报告不能代替运行证据。

## 现实裁决

保留独立 TaoWind-Next-Internet 仓库及 candidate 分支。OPP 已拥有六协议族和精确 RCP 契约协商，采用薄 Adapter + 固定版本源码依赖；不同生命周期保持独立。TINP 未破坏性拆解，原始源码与旧测试完整保留，组合层逐步接管跨协议 Profile。RCL 编译运行事务、迁移和路由约束。RNCS/RFE 的事实、模拟和现实提交保持原 Owner，本版没有把 worldId 字段冒充跨世界集成。

## 安全修复与回验

初审报告 `audit/security-review.md` 保留初始漏洞及红灯状态。最终修复如下，测试保留在 `tests/security-review.test.mjs`：

- 成功执行前核查、执行后持久消费会话证据锚点。精确重试可取原回执，分叉请求拒绝。
- 不信任主体声明的费用；使用服务端受信边配置汇总，并由实际 RCL 路由守卫裁决签名租约预算。
- 绑定 authority-signed session 的源节点与真实 path 起点。
- 正确签名的回执仍必须匹配主体、世界、能力、节点、会话、版本、路径、请求与结果。
- TCP 连接、待决请求和异步 handler 限制为 64；延迟尚未发送的消息在超时/关闭时取消。

独立审查最终八项安全用例通过，完整发行验证在 `tests.tap` 再次执行。三类 RCL 独立规则测试和集成规则负测共同确认实际接入。

联调时一次并行全套测试在 TCP 路径发生响应超时：远端已经执行，调用端切换到备用路由。原因未被缩小到特定操作系统事件，不将顺序重跑当作根因修复。本版补了精确签名请求对账恢复；独立注入“真实远端执行后丢弃响应”验证仅执行一次。已用顺序发行验证限制故障测试互相争抢资源；真实高负载网络与超时分布仍未验证。

## 证据级别

当前交付目标是 **VERIFIED_LOCAL_CANDIDATE**，不是军事部署等级、商业 SLA 或 F5/F6。真实运行指本机 OS 子进程、UDP/TCP 回环传输、实际 Python OPP 及 RCL JS lowering，不指公网、多机器硬件或原生 RCL VM。

本地路由故障、Provider 替换、版本兼容、主体迁移、磁盘回执与篡改拒绝具有直接见证。许可不明的 OPP 仅作内部第一方快照；无公开发布。K400 九门全部保持独立裁决 `NOT_ADJUDICATED`，没有核准单元 PASS。
