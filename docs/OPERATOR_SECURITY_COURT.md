# 外部操作员授权安全审查

范围：TINP v0.1.0-alpha.4 在现有未决请求维护入口增加可选外部操作员公钥指纹固定、AAF 限定批准回执和历史终态验签。本审查独立检查已有恢复路径，提出安全约束并实现攻击集成测试；未修改产品源码。

## 准入模型

首次公钥指纹固定仍需本机用户明确操作。固定后，`confirmed:true` 只表达本地确认，不能代替外部签章。已固定策略不能被替换或降级；保护 checkpoint 与签名账本中的策略历史相互核验。

批准内容绑定未决请求、整个租约、会话、主体、世界、连续性根、协调器公钥指纹及固定策略。AAF 负责批准数据与签章格式；TINP 限定角色、动作范围、空条件、严格时间区间和公钥指纹；RCL 保留退役不变量。外部 keyring 仅在调用时输入，没有纳入 checkpoint 或账本。

测试签名私钥仅存在于 `tests/operator-coordinator.fixture.mjs` 的独立 signer 子进程。测试主体通过 IPC 获得公钥和签好的批准回执，再提供给 TINP；不向 TINP 提供该签名私钥。其他协调器自有测试密钥继续遵循已有 DPAPI 夹具边界。

## 攻击及实际验证

`tests/operator-security.test.mjs` 覆盖以下 8 项集成场景。最终发行退出码和源码哈希由 `evidence/0.1.0-alpha.4/` 的正式验证产物确定。

本次独立集成运行实际结果：8/8 通过，0 失败、0 跳过，耗时 90.88 秒。此结果对应审查时的工作树；发行时仍由主验证流程对最终源码整体运行。

| 攻击或恢复条件 | 要求的结果 |
| --- | --- |
| 重复固定同一密钥，或试图替换已固定密钥 | 同一策略可幂等确认；替换失败；不保存外部公钥 keyring 或私钥；重启后的挑战根保持一致 |
| 仅布尔确认，缺少 keyring，替换公钥或标记密钥已撤销 | 在第一次租约撤销前拒绝，协调器及三个节点密文和账本字节不变 |
| 有效外部签名但挑战、签者、范围或有效期错误 | 同样不能触发租约撤销 |
| 三节点实际持久确认后，外部 keyring 更新为已撤销 | 重新核验当前授权并拒绝 terminal；pending 保留，已撤销租约不回退 |
| 等待节点确认期间批准真实过期 | 第二次授权核验失败，不生成 terminal，不清 pending |
| 有效 DPAPI checkpoint 中删除或替换固定策略 | 与签名策略历史不一致，状态查询和恢复均拒绝 |
| terminal 已写而 pending 尚未清除时，真实终止协调器，之后等待批准过期 | 可以依据已记录的有效准入时刻恢复历史终态；仍须提供当前未撤销的外部密钥；不执行请求、不更新租约 |
| 协调器重新签署包含伪造外部签章、降级本地确认或篡改准入时间的 terminal | 外部验签或时间核验失败；协调器的签名不能代替外部批准 |

历史过期恢复样本还在 pending 清除后重新检查已撤销的外部 keyring，防止状态查询跳过已终止请求的签章验证。真实崩溃样本持续观察三个节点执行数为零，并比较恢复前后的租约根。

## 审查要求对实现的影响

本轮强调了以下现有恢复路径容易遗漏的约束：固定策略必须进入所有恢复快照和签名历史；terminal 位于 checkpoint 前缀及 pending 已清除时仍须外部验签；两次准入必须分别检查批准有效期和当前 keyring 撤销元数据；RCL 之后写入终态前的授权结果不能沿用过期缓存；固定公钥按 SPKI DER 计算指纹；历史准入时刻必须与终态时间以及签名有效区间一致。

## 未覆盖和信任边界

- 首次固定策略是本机明确引导，没有外部身份目录或独立设备证明，不等同于完成生产操作员身份部署。
- 外部 keyring 的公钥和撤销元数据由调用者提供。本轮不证明它们来自持续在线的权威撤销服务。
- 历史准入时间来自协调器签名账本和本机时钟，属于协调器认证的本机时间记录，不是独立时间戳服务。掌握协调器私钥并可重写整个状态的人不在本机防回滚保证内。
- 没有解决整目录旧快照回滚、硬件密钥托管、跨设备审批、网络范围撤销收敛或生产操作员轮换。
- 终态仍表示整个租约退役以及原执行结果未知；外部批准不续租、不创建新会话权限、不撤销已经发生的执行。
- 本地 Windows 进程及回环网络证据不代表公网部署、通用副作用事务、RCL Core 晋升或 K400 裁决。
