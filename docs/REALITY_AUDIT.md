## Implemented assets versus declarations

OPP is a real exchange-protocol family: CHP, RCP, RXP, RAP, REP, RSP plus schema validation, bridge tools and bounded native invocation. Its capability agreement is not an authenticated authority lease. DHSC has source-bound registry/governance and delegates OPP; neither source supplies this complete network transaction loop. Current OPP tests pass 41/41 with UTF-8 configured. The initial locale-dependent OPP run had 3 failures and 1 error. DHSC has 41 pass / 2 fail on untouched OPP; its existing hash-checked installed UTF-8 overlay produces 43/43. That overlay does not change upstream source and is not part of this network adapter's execution route.

RCL already expresses typed records and executable authorization/state predicates. Its fixed transaction and migration programs run through the canonical compiler and JavaScript runtime. Static Text facets in TINP's original RCL file describe requirements without enforcing them. Native VM/compiler execution and full RCL regression were not performed. RNCS has actual source for authority-constrained world transport/roaming and RFE world-fact storage; this product has no live RNCS adapter and cannot perform RNCS commits.

The supplied Reality Network Runtime ZIP has a real RNCS/AAF/RSR/RFE multiplayer synchronization runtime. Original local deterministic loopback tests passed 20/20. This older release is distinct from the current RNCS main-95 source pin. Memory World Tree's supplied finite reference model passed 25/25 original tests. BIGS-OS v1.0's supplied ZIP explicitly contains a unified specification baseline; no BIGS production runtime was verified. Supplied UPDIA-RNLM is an isolated developmental research lab, explicitly not a canonical UPDIA replacement; training and canonical UPDIA runtime execution were not performed.

## Three local profiles

The independent `tests/profiles.test.mjs` run passed 10/10 on the source hashes recorded in `evidence/profiles-review-summary.json`; its raw TAP is `evidence/profiles-tests.stdout.txt`. It verifies process IDs, live bound loopback endpoints, hop-by-hop frame/byte counters, actual provider execution counts and signed/durable receipt continuity.

- Degraded conditions: kill relay B; block a link while B remains alive; block a network partition on both sides; disable every provider; apply real send-rate delay. Alternate A–C, local isolated execution and survival-without-result are separately asserted. These are local fault-injection results, not military certification.
- Commercial continuity: contract-identical replacement, semantic-drift rollback, incompatible-version fallback, source migration and durable evidence-prefix preservation. Production enrollment, fleet upgrades, billing, guaranteed SLA and distributed side-effect rollback remain absent.
- Everyday use: `我要使用字符计数能力完成：你好，互联网🌏` is parsed without user IP, port, provider ID or transport input. The capability/parser is deliberately narrow; no general natural-language intent understanding is claimed.

The strict bandwidth test isolates raw DISCOVER transport timing from Python OPP/RCL overhead. Its recorded run transferred 4,916 probe bytes at 16,000 B/s in about 357 ms, versus a nominal 307.25 ms; complete execution transferred 15,440 bytes. These are local measurements on the pinned run, not future performance promises.
