## Implemented assets versus declarations

OPP is a real exchange-protocol family: CHP, RCP, RXP, RAP, REP, RSP plus schema validation, bridge tools and bounded native invocation. Its capability agreement is not an authenticated authority lease. DHSC has source-bound registry/governance and delegates OPP; neither source supplies this complete network transaction loop. Current OPP tests pass 41/41 with UTF-8 configured. The initial locale-dependent OPP run had 3 failures and 1 error. DHSC has 41 pass / 2 fail on untouched OPP; its existing hash-checked installed UTF-8 overlay produces 43/43. That overlay does not change upstream source and is not part of this network adapter's execution route.

RCL already expresses typed records and executable authorization/state predicates. Its fixed transaction and migration programs run through the canonical compiler and JavaScript runtime. Static Text facets in TINP's original RCL file describe requirements without enforcing them. Native VM/compiler execution and full RCL regression were not performed. RNCS has actual source for authority-constrained world transport/roaming and RFE world-fact storage; this product has no live RNCS adapter and cannot perform RNCS commits.

The supplied Reality Network Runtime ZIP has a real RNCS/AAF/RSR/RFE multiplayer synchronization runtime. Original local deterministic loopback tests passed 20/20. This older release is distinct from the current RNCS main-95 source pin. Memory World Tree's supplied finite reference model passed 25/25 original tests. BIGS-OS v1.0's supplied ZIP explicitly contains a unified specification baseline; no BIGS production runtime was verified. Supplied UPDIA-RNLM is an isolated developmental research lab, explicitly not a canonical UPDIA replacement; training and canonical UPDIA runtime execution were not performed.

## Three local profiles

The independent `tests/profiles.test.mjs` run passed 10/10 on the source hashes recorded in `evidence/profiles-review-summary.json`; its raw TAP is `evidence/profiles-tests.stdout.txt`. It verifies process IDs, live bound loopback endpoints, hop-by-hop frame/byte counters, actual provider execution counts and signed/durable receipt continuity.

- Degraded conditions: kill relay B; block a link while B remains alive; block a network partition on both sides; disable every provider; apply real send-rate delay. Alternate A–C, local isolated execution and survival-without-result are separately asserted. These are local fault-injection results, not military certification.
- Commercial continuity: contract-identical replacement, semantic-drift rollback, incompatible-version fallback, source migration and durable evidence-prefix preservation. Production enrollment, fleet upgrades, billing, guaranteed SLA and distributed side-effect rollback remain absent.
- Everyday use: `我要使用字符计数能力完成：你好，互联网🌏` is parsed without user IP, port, provider ID or transport input. The capability/parser is deliberately narrow; no general natural-language intent understanding is claimed.

The strict bandwidth test isolates raw DISCOVER transport timing from Python OPP/RCL overhead. Its recorded run transferred 4,916 probe bytes at 16,000 B/s in about 357 ms, versus a nominal 307.25 ms; complete execution transferred 15,440 bytes. These are local measurements on the pinned run, not future performance promises.

The full suite may have newer cumulative validation logs; consult its final ledger for totals. Partial local evidence never compensates for an untested K400 gate. K057/K110/K117/K250/K257 are reviewed stress candidates, not newly admitted cells.

## alpha.5 external recovery witness

The current candidate adds an opt-in `twni.external-recovery-anchor.v1` adapter. It was exercised with a separate signer process and a complete old-directory replay: sequence 2 was signed externally, the older copy failed closed with `RECOVERY_ANCHOR_ROLLBACK`, and the newer copy reopened with the original lease. The keyring and signer private key were not written to the protected coordinator state. This remains a local candidate; the keyring, witness registry, clock, code/configuration release, and post-anchor suffix are not independently authenticated.

## alpha.6 authority registry witness

The current candidate also adds an opt-in `twni.authority-registry.v1` adapter. A separate issuer child signs a seq1 snapshot and a seq2 append-only rotation snapshot. Verification binds the registry and policy roots, issuer SPKI fingerprint, sequence/previous root, immutable member identity fields, predecessor epoch, role-subset rotation and revoked state. A caller-supplied member keyring is checked against the recorded fingerprints and projected to the existing operator/recovery keyring shape; the `recovery-anchor` CLI can use this bridge for one invocation.

The local demo and tests exercised issuer replacement/revocation, forged roots/signatures, chain rollback, key resurrection, role escalation, duplicate active authority, accessor/inherited objects, expired snapshots and missing/mismatched member keys. No private key is serialized by the registry or checkpoint. This is still an offline local candidate: registry files, issuer custody, member key material, `nowMs`, publication, revocation distribution, transparent logging, trusted time, hardware protection, cross-device recovery and post-snapshot suffix integrity remain unproved. Formal-gate pin/fingerprint and AAF revocation-registry code were used only as bounded donor references; no RCL Core primitive was changed or promoted.

## alpha.7 authority registry distribution witness

The current candidate adds an opt-in `twni.authority-registry-distribution.v1` bundle. A separate issuer child signs one registry snapshot and three separate mirror children sign receipts that bind its registry root, sequence and policy root. Local verification accepts a threshold quorum, rejects a validly signed conflicting root as `AUTHORITY_REGISTRY_DISTRIBUTION_FORK_DETECTED`, and rejects a one-receipt bundle as `AUTHORITY_REGISTRY_DISTRIBUTION_QUORUM_INSUFFICIENT`. The CLI reads caller-supplied bundle, policy and mirror keyring files and does not write coordinator state.

This proves same-call offline consistency for the supplied receipts. It does not prove an online mirror service, durable cross-host convergence, trusted time, transparent history, mirror revocation publication, hardware key custody, cross-device recovery or code/configuration anti-rollback. The mirror policies and keyrings remain caller-selected inputs; no RCL Core, RNCS world authority or AAF owner changed.

## alpha.8 authority registry historical convergence witness

The current candidate adds an opt-in `twni.authority-registry-convergence.v1` bundle. The independent issuer and three mirror children sign two sequential registry snapshots; each snapshot is wrapped in a distribution quorum, and the convergence verifier accepts the contiguous Genesis→sequence-2 history with the same three accepted mirrors. The local witness also creates a valid same-sequence alternate issuer root and a threshold-valid bundle with a smaller mirror set; verification rejects the supplied history with `AUTHORITY_REGISTRY_CONVERGENCE_FORK_DETECTED` and `AUTHORITY_REGISTRY_CONVERGENCE_MIRROR_SET_DRIFT`. The CLI and six focused tests exercise the same contracts, including sequence gaps, broken predecessors, duplicates, altered history roots and accessor inputs.

This is evidence about the finite history supplied to one local call. It does not prove that omitted snapshots were never published, that mirrors converge across hosts or restarts, that timestamps are trusted, or that an online transparency/revocation service, hardware custody, cross-device recovery or post-history anti-rollback exists. No private key is serialized by the convergence bundle; no RCL Core, RNCS world authority or AAF owner changed.
