# 未决请求处置安全审查

审查范围：TINP v0.1.0-alpha.3 的 Windows 本机未决状态查询、maintenance 隔离、明确退役整个租约、三节点持久撤销确认及终态恢复。此次审查独立读取现有恢复实现后提出攻击用例，未修改产品源码。最终测试退出码及源码哈希以本版 `evidence/0.1.0-alpha.3/` 为准。

## 实际验证

`tests/pending-security.test.mjs` 包含 8 项集成测试，使用真实 DPAPI 文件、真实 A/B/C 子进程与实际本机网络；退役崩溃测试使用另一个协调器进程，在真实写入后由父进程终止。

局部验证：最初 7 项通过；随后新增的仅 RCL 事实根损坏变体暴露一个证据绑定缺陷。修复后，扩展终态攻击与新增未决绑定两项测试均通过，实际耗时 16.01 秒。完整发行回归由主验证流程统一执行，不能将这些分批结果冒充最终源码的完整运行结果。

| 场景 | 必须维持的不变量 |
| --- | --- |
| 离线与在线状态查询 | 协调器密文、三个节点密文及账本字节不变；输出没有原始文本和私钥；不存在的状态路径不被创建；`nodeCacheVerified:false` |
| maintenance 执行旁路 | `use`、直接 `wire(INTENT)`、重启 C 后直接向 A 的 IPC 发送执行转发包均拒绝；执行数保持零 |
| 错误请求根或缺少明确确认 | 在检查失败前不改撤销水位、账本或 checkpoint |
| 有效 DPAPI 内部未决根、目标或路由内容被改 | 即使签名请求及 routeRoot 不变，查询与正式恢复也必须拒绝；查询失败不写文件 |
| B 节点死亡导致确认不全 | 保留 pending，整个租约已撤销，不能生成成功终态；恢复 B 后完整重试可以完成；不签发新租约 |
| terminal 已写且 checkpoint 已更新，尚未清除 pending | 实际终止协调器后恢复原终态，只清 pending，不重发，不新增 terminal，不更新租约 |
| terminal 已写而 checkpoint 尚未更新 | 同样从验签后的账本后缀恢复；三节点执行数为零 |
| authority 有效签名但错误终态语义 | 拒绝缺失或重复节点确认、错误节点签名、错误撤销水位、伪造 RCL 程序根或事实根，保留 pending |

退役终态固定使用 `executionOutcome:'unknown'`。撤销只能阻止后续执行，不能证明原请求从未执行，也不能撤销过去已发生的执行。本轮测试中的零执行数是所构造的发出前未决样本的实际观测。

## 审查影响

审查指出并纳入实现或测试的关键点包括：maintenance 对节点重启的隔离不能被 `activate` 绕开；撤销确认必须覆盖固定三个节点且绑定请求根、租约根和水位；终态可能已位于 checkpoint 前缀，不能只检查后缀；离线查询不得通过恢复初始化路径写文件；未决选择必须绑定签名请求；RCL 终态证据必须绑定重算的程序、状态及事实根。

仅篡改 RCL `factsRoot` 的攻击曾真实复现错误接受：其他根保持正确且终态仍有 authority 签名时，恢复路径清除了 pending。实现随后增加对重算后事实根及结果代码的核验；包含该变体的扩展攻击测试已重新通过。不能用重新计算得到 `allowed` 替代对已记录证据的完整绑定验证。最终发行结论仍取决于本版正式回归日志。

## 证据和权限边界

- 明确确认来自本机 Windows 用户调用维护入口，是测试夹具的操作边界；不是外部生产操作员身份认证或人类签章。
- 同用户完全掌握目录与密钥时，本系统不能提供外部可信防回滚锚点；整目录旧快照回滚仍未解决。
- 状态查询校验 DPAPI checkpoint、签名账本和可见终态；不验证节点缓存，不证明服务可达性。
- 终态恢复需验证三节点持久确认，并重新运行固定 RCL 守卫。Node 装配、Python/Windows 存储和本机网络属于执行 Provider；没有 RCL Core 或 K400 晋升。
- 这些测试不构成公网、跨设备、通用副作用事务或网络范围撤销收敛的证明。
