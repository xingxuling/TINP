# TINP 术语表

这页只做一件事：把 README 和架构文档里的术语翻成普通话。

| 术语 | 简单解释 |
|---|---|
| **Continuity Root** | 用来表示“这是同一个主体连续状态”的根标识，不等于真实世界身份证明 |
| **Authority Registry** | 记录哪些签署方、角色和公钥在当前规则下被认可的候选注册结构 |
| **Evidence Ledger** | 按顺序保存执行证据并用哈希链连接起来的账本 |
| **Recovery Anchor** | 外部保留的已知可信恢复锚点，用来帮助发现回退或旧状态替换 |
| **Pending** | 系统无法确定请求是否已经完成时保留的未决状态；默认不盲目重发 |
| **Provider** | 实际提供某个能力并执行请求的节点或服务 |
| **Lease** | 有期限、有限范围的权限授权，不等于永久权限 |
| **Receipt** | 一次执行、验证或状态变化对应的回执 |
| **Fail-closed** | 无法确认时默认拒绝继续，而不是假设安全或成功 |
| **OPP** | 描述能力、输入输出、兼容性和桥接关系的协议与工具层 |
| **CHP / RCP** | OPP 中用于握手和能力协商的协议；协商成功不等于已经获得权限 |
| **Loopback** | 同一台机器上的回环网络测试，不等于两台真实设备之间的生产网络 |
| **Convergence** | 多份历史或状态是否按规则保持一致、连续且没有分叉 |

## 一个重要原则

TINP 文档里的术语描述的是**软件状态和验证边界**。它们不自动代表：

- 真实人类身份；
- 法律授权；
- 生产安全认证；
- 互联网规模共识；
- 外部机构背书。

如果只想快速理解项目，先读 README；只有遇到这些术语时再回来查这页即可。
