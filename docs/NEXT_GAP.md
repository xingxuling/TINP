# 下一最短真实缺口

v0.1.0-alpha.2 已将 Windows 本机密钥、会话、已消费锚点、撤销状态和回执接入真实持久恢复。RCL 恢复准入保持主体、世界、连续性根、租约期限及证据前缀。节点重启先接收签名撤销水位，再获准接收执行请求。完整证据见本版版本目录。

当前最高优先级的产品缺口是未决请求处置：若协调器在发出前崩溃，恢复查询不到回执，系统保持 PENDING 状态拒绝继续，防止未经确认的重复执行。需要将只读状态查询、明确拒绝原因与经鉴权的处置决定呈现给使用者。不能把自动清除 checkpoint 或重新发请求当恢复。

安全缺口是外部防回滚锚点与跨设备密钥生命周期。同一用户恢复整个旧目录快照，当前 DPAPI 加签名账本不能判断全局时间倒退。节点孤立期间也不能即时获知外部撤销。需要独立可信锚点、明确时间偏差和重连协议，保持恢复不等于重新授权。

随后引入成熟 TLS/QUIC Provider，在两台真实设备验证身份部署、撤销同步、断网恢复。现有回环夹具不能直接发布公网。真实设备和密钥托管需要相应实证，不以本机测试替代。

现有 RCL 能表达本轮不变量，无需修改 Core。下一轮仍先审计 Owner，再决定候选 Profile、Provider 或可复现 RCL_GAP。RNCS/RFE 世界事实与提交保持原归属。
