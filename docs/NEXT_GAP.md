# 下一最短真实缺口

alpha.3 已补本机只读状态检查、维护模式原回执查询、显式停用整个旧租约的未决关闭。两项行为保持区分：查回回执能确认历史结果；终止未决只表示不再继续该租约，结果未知仍保留。没有提供“忽略未知后重新执行”。

下一优先级是独立操作员授权与恢复锚点：当前 CLI 与 Windows 当前用户共享 DPAPI 访问，本机用户可操作自己的测试夹具，却不构成独立人类授权签章、多租户治理或生产密钥托管。需要先确定外部 authority Owner、签发/撤销/轮换语义与可信锚点来源，不能在本仓库凭空重造 RNCS authority 或自动发新 lease。

整目录旧快照、外部时间与跨设备密钥迁移仍需独立可信来源。随后才进入成熟 TLS/QUIC Provider 的两台真实设备验证；单机进程与回环网络不能替代真实异机证据。

当前 RCL 已能表达恢复及未决退休规则，新增固定 Profile 就足够。本轮未发现应修改 Core 的可复现表达缺口。RCL_INTEGRATION_GAP 和 PLATFORM_PROVIDER_GAP 有本机证据，外部锚点与 authority adapter 仍为未实施，不自行升格 K400。
