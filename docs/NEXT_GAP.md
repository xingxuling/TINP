# 下一最短真实缺口

本轮停止边界是可运行且可复核的本机三节点闭环，已满足本轮最小产品实验。下一轮优先补持久重启恢复，而非继续铺开协议编号。

当前节点重启会更换临时签名密钥，协调器也不会恢复主体私钥、会话签发状态和撤销集。已有证据文件可重读校验，但这不等于服务可恢复。先建立本地受保护的密钥 Provider 接口，恢复会话/已消费证据锚点/撤销状态，再故意杀死协调器与目标进程，验证不会重发未经确认的高影响动作或产生证据分叉。保持只读能力作为最小复验场。

第二个缺口是隔离后撤销与证据对账：节点离线期间不可能即时获知新撤销，本版只保证已经接收的撤销立即阻断及已有租约到期失效。需要设计带版本、时钟偏差边界和已签撤销水位的恢复握手；不能把重连等同恢复授权。

第三步才是成熟 TLS/QUIC Security Provider 与两台真实设备。当前回环身份夹具不能直接放到公网。真实密钥托管、账号/硬件操作或生产发布另行进入对应授权边界。

RCL 无需先改 Core：本轮固定源码已经表达事务、迁移及路由准入。应先复用这些规则，把新恢复状态变换的正负例作为下一 Stress Case，再判断是否存在可复现 Primitive/IR/Runtime 缺口。RNCS/RFE 世界事实与提交仍归原 Owner。
